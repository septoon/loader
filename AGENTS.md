## Главные ограничения

- VPS с примерно 3 GB свободного диска — оркестратор и транспортный узел, не хранилище медиофайлов.
- Нельзя полностью staging-ить крупный исходник на VPS. Любой временный disk/RAM cache должен быть ограничен и учитывать свободное место.
- Финальное хранилище — Yandex Disk, основные каталоги: `/Media/Movies` и `/Media/TV`.
- Для обычного HTTP URL сначала рассматривай официальный remote import Yandex Disk. Для torrent используй последовательное чтение и bounded piece-cache.
- Не считай Yandex resume/`Content-Range` рабочим, пока это не подтверждено реальным API-тестом.
- Сейчас транскодирование не нужно.
- Сохраняй возможность позже получить временную download URL Yandex Disk и открыть её в VLC напрямую, без проксирования видеобайтов через VPS. VPS proxy — только fallback.

## Безопасность и эксплуатация

- Не коммить и не логируй OAuth token, client secret, cookies и временные download URL.
- Секреты храни только в игнорируемом `runtime/secrets/` или переменных окружения; файлы секретов должны иметь права `0600`.
- Используй только официальные Yandex OAuth/Disk API для авторизации и файловых операций.
- Проверяй SSRF, path traversal, имена файлов, лимиты размера, свободное место, subprocess arguments и ownership задач.
- Опасные операции, деплой, commit и push выполняй только после явного разрешения пользователя.

## Инженерный порядок

- Сначала проверяй реальный data path, затем меняй архитектуру.
- Не добавляй полный staging как скрытый fallback.
- Для WebTorrent зафиксирована версия `3.0.21`; используемые в PoC private API требуют отдельной проверки при обновлении.
- После изменений запускай минимальную релевантную проверку и записывай фактический результат.
- Перед завершением каждой рабочей сессии обязательно обновляй минимум `docs/PROGRESS.md` и `docs/HANDOFF.md`.
